# Contributing

Small, evidence-backed improvements are welcome.

## Useful contributions

- Correct a misleading claim or unsafe editing instruction.
- Update provider rollout status with a dated official source.
- Document a hosted-platform workflow verified against its current official documentation.
- Add a minimal example of a parser or deployment edge case.
- Improve clarity without turning the prompt into an opaque autonomous script.

## Before opening a pull request

1. Explain the problem and the smallest fix.
2. Link primary documentation for technical or rollout claims; distinguish announcements from deployed behavior.
3. Date status updates. Never silently convert a future promise into a live-support claim.
4. Check Markdown links and code fences.
5. Check that examples preserve unrelated rules and do not add broad search or user-fetch blocks.
6. Check the empty-user-agent-group, duplicate-group, existing-Allow, generated-file, missing-file, hosted-platform, and repeat-run cases.
7. Keep credentials, site backups, private URLs, and personal information out of issues and commits.

This repository contains documentation and prompts, not a deployment service or production-tested universal robots.txt parser. Do not describe a documentation check as a successful live-site deployment.

By submitting a contribution, you agree that it can be distributed under the repository's MIT license. Linked third-party documents remain under their respective terms.
